# Тестовый сервис для тестирования через Kafka

Сервис предназначен для использования в процессе тестирования асинхронных вызовов и завершений.
В том числе для небольших нагрузочных тестов в районе 10–50 RPS. Первая версия не рассчитана на несколько реплик.

## API

### Конфигурация 

cluster: "localhost:9092"
publisherTopics: [
  "regEx1",...,"regExN"
]
autoDeleteSlotsSeconds: int
consumerIdleSeconds: int
consumerGroupName: string
defaultWaitSeconds: int

Публиковать можно только в топики, попадающие под одно из регулярных выражений. Если список пуст — ограничений нет.

Если autoDeleteSlotsSeconds не указан, по умолчанию используется 1 минута.
Если consumerIdleSeconds не задан, по умолчанию используется 1 час.
Если defaultWaitSeconds не указан, по умолчанию используется 1 минута.

### Publishing 

Используется Kafka REST API

POST /api/v1/topics/{name}/records?ack=0/1

Формат сообщения `RecordDto`:

``` json
{
  "headers": [
        {
            "name": "Header-1",
            "value": "SGVhZGVyLTE="
        },
        {
            "name": "Header-2",
            "value": "SGVhZGVyLTI="
        }
    ],
    "key": {
        "type": "BINARY",
        "data": "Zm9vYmFy"
    },
    "value": {
        "type": "JSON",
        "data": {
            "foo": "bar"
        }
    }
}
```

Возврат: 201 + {} — если отправка подтверждена; 202 + {} — если сообщение принято к отправке; 400 — если топик недопустим.

### Проверка/чтение записей

Перед началом операции регистрируется слот с проверками, обычно через идентификатор корреляции (`correlationId`). С момента регистрации слота
результаты проверок начинают заполняться.
Затем инициируется операция, после чего проверяются результаты проверок с возможностью ожидания.

#### POST /api/v1/slots

Тело запроса:

``` json
{
   "topic": string,
   "autoDeleteSeconds": int,
   "checks" : [      
		{
			"headers" : [
				{
					"name": string 
                    "value": string   				
				},
			],	
			"values" : [
				{
					"jsonPath" : string
					"value": string
				}
			]				
		}
   ] 
}
```

Возврат

``` json
{
	"id": string
}
```

Если autoDeleteSeconds не задан, используется значение параметра autoDeleteSlotsSeconds.

Чтобы сообщение удовлетворяло проверке, все параметры должны совпасть.

#### POST /api/v1/slots/{id}/checks/{index}/wait?n=NNNN&timeoutMs=ms

Ожидание, пока под проверку попадёт NNNN записей; по умолчанию — 1.

Ответ: 200 {} или 504 {}. 

#### GET /api/v1/slots/{id}/checks/{index}/count

Число записей, попавших под проверку.
Ответ 200 `{ "count": int }`.

#### GET /api/v1/slots/{id}/checks/{index}?offset=N&count=M

Чтение записей, попавших под проверку.

Возврат 200 + RecordDto[].

M — по умолчанию 20.

#### DELETE /api/v1/slots/{id}

Удаление ненужного слота до истечения autoDeleteSeconds. 200 + {}, 404. Все незавершённые запросы ожидания прерываются с кодом 409.

## Реализация

При открытии слота проверяется, что есть соответствующий консюмер. Если его нет, он создаётся, для него заводится список слотов. Также обновляется время, до которого консюмер должен жить: now() + consumerIdleSeconds + slot.autoDeleteSeconds, если оно больше текущего значения. Периодический таймер раз в 10 минут проверяет список и удаляет устаревшие элементы.

Консюмер отправляет каждую полученную запись в коллекцию слотов для сверки. Слот накапливает все подходящие ему записи.

Запрос ожидания регистрирует в коллекции слотов запись с `promise`, содержащую условие срабатывания и тайм-аут. При поступлении новой записи в слот проверяются ожидающие запросы.

При срабатывании тайм-аута запись с `promise` удаляется из коллекции. Необходимо избегать взаимных блокировок при операциях с коллекциями.

Синхронных ожиданий быть не должно. Блокировки при манипуляциях с коллекциями разрешены.
