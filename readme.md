# Тестовый сервис для тесирования через Kafka

Сервис предназначен для использования в процессе тестирования асинхронных вызвовоа и завершений.
В том числе и небольших нагрузочных тестов в районе 10-50 RPS. 1я версия не рассчитана на несколько реплик. 

## API

### Конфигурация 

cluster: "localhost:9092"
publisherTopics: [
  "regEx1",...,"regExN"
]
autoDeleteSlotsSeconds: int
consumerIdleSeconds: int
consumerGroupName: string
defaultWaitSeconds: int

Публиковать можно только в топики, попадающие под один из regex. Если список пуст - ограничений нет.

если autoDeleteSlotsSeconds не указан, то 1 минута
если consumerIdleSeconds не задан, то 1 час.
если defaultWaitSeconds не указан, то 1 минута

### Publishing 

Используется API Kafka REST  

POST /api/v1/topics/{name}/records?ack=0/1

Формат сообщения RecordDto

``` json
{
  "headers": [
        {
            "name": "Header-1",
            "value": "SGVhZGVyLTE="
        },
        {
            "name": "Header-2",
            "value": "SGVhZGVyLTI="
        }
    ],
    "key": {
        "type": "BINARY",
        "data": "Zm9vYmFy"
    },
    "value": {
        "type": "JSON",
        "data": {
            "foo": "bar"
        }
    }
}
```

Возврат: если 201 + {} - если подтверждена отправка, 202 + {} - если принято к отправки. 400 - если не валидный топик

### Проверка/чтение записей

Перед началом операции регистрируется слот, с проверками, обычно через correlationId. С момента регистрации слота, 
результаты проверок начнают заполняться.
Затем инициируется операция и потом проверяются результаты проверок, с возможностью ожидания.

#### POST  /api/v1/slots

Body:

``` json
{
   "topic": string,
   "autoDeleteSeconds": int,
   "checks" : [      
		{
			"headers" : [
				{
					"name": string 
                    "value": string   				
				},
			],	
			"values" : [
				{
					"jsonPath" : string
					"value": string
				}
			]				
		}
   ] 
}
```

Возврат

``` json
{
	"id": string
}
```

Если autoDeleteSeconds не задано - то используется общий.

Чтобы сообщение удовлетворяло проверке, все параметры должны совпасть.

#### POST /api/v1/slots/{id}/checks/{index}/wait?n=NNNN&timeoutMs=ms

Ожидание, пока под проверку попадет NNNN записей, по умолчанию - 1

Ответ: 200 {} или 504 {}. 

#### GET /api/v1/slots/{id}/checks/{index}/count

Число записей попавших прод проверку. 
Ответ 200 `{ "count": int }`

#### GET /api/v1/slots/{id}/checks/{index}?offset=N&count=M

чтение записей в проверке.

Возврат 200 + RecordDto[]

M - по умолчанию 20.

#### DELETE /api/v1/slots/{id}

Удаление ненужного слота до истечения autoDelete. 200 + {}, 404. Все ожидающие wait заппросы прерываются с 409.

## Реализация

При открытии слота проверяется, что есть соответсвующий консюмер. Если нет - создается, для него заводится список слотов. Также если список, до которого времени консюмер должен жить: now() + consumerIlde + slot.autoDelete, если больше текущего значения. Переиодический таймер 10 мин, проверяет список и удаляет устаревшие.

Консюмер отправляет каждую полученную запись в коллекцию слотов, для сверки. Слот накапливает все подходящие ему записи. 

Запрос на wait регистрирует свою запись с promise в коллекции слотов с описанием условия срабатывания и таймаутом. При поступлении новой записи в слот - проверяются ожидающие. 

При срабатывании таймаута - запись с promise удаялется из коллекции. Необходимо избегать deadlocks при операциях с коллекциями. 

Синхронных ожиданий не должно быть. locks при манипуляциях с коллекциями - разрешены.
