Документ описывает параметры конфигурации сервиса, их типы, значения по умолчанию, ограничения и влияние на публикацию, консюмеров и жизненный цикл слотов. Контракт HTTP API описывается в [`api.md`](api.md), а внутреннее устройство и алгоритмы работы — в [`architecture.md`](architecture.md). Назначение проекта, требования к запуску и инструкции по сборке остаются в [`../readme.md`](../readme.md); правила документирования определены в [`../AGENTS.md`](../AGENTS.md).

## Общие правила конфигурации

| Параметр | Тип | Обязательность | Значение по умолчанию | Ограничения | Влияние на поведение сервиса |
| --- | --- | --- | --- | --- | --- |
| `cluster` | строка | Да | Нет | Формат `хост:порт`; непустые хост и порт; порт от `1` до `65535` | Определяет общий нативный адрес Kafka для публикации, чтения и управления собственными группами |
| `httpHost` | строка | Нет | `127.0.0.1` | Непустой адрес прослушивания IPv4 или IPv6; значение по умолчанию — петлевой адрес IPv4 | Определяет сетевой интерфейс, на котором сервис принимает HTTP-запросы |
| `httpPort` | целое | Нет | `3000` | От `1` до `65535` включительно | Определяет TCP-порт HTTP-сервера нашего сервиса |
| `publisherTopics` | массив строк | Нет | Пустой список | Каждый элемент — регулярное выражение; пустой список допустим; в переменной окружения задаётся JSON-массивом строк | Разрешает публикацию только в соответствующие топики; на наблюдение через слоты не влияет |
| `autoDeleteSlotsSeconds` | целое, больше нуля | Нет | `60` секунд (1 минута) | От `1` до `2147483647` включительно; применяется при отсутствии `autoDeleteSeconds` в запросе | Задаёт срок автоматического удаления слота по умолчанию; очистка выполняется планировщиком раз в 1 минуту |
| `consumerIdleSeconds` | целое, больше или равно нулю | Нет | `3600` секунд (1 час) | От `0` до `2147483647` включительно; интервал проверки 10 минут параметром не настраивается | Определяет дополнительное время жизни консюмера после закрытия последнего слота |
| `consumerGroupPrefix` | строка | Нет | `testing-REST-API` | Непустое значение; допустимы символы имени группы Kafka: латинские буквы, цифры, точка, дефис и подчёркивание | Участвует в формировании отдельной группы консюмера для каждого топика |
| `defaultWaitSeconds` | целое, больше нуля | Нет | `60` секунд (1 минута) | От `1` до `2147483647` включительно; применяется при отсутствии `timeoutMs` в запросе | Задаёт тайм-аут ожидания записей по умолчанию и не влияет на накопление записей или срок жизни слота |

Правила:

- Все временные параметры задаются в секундах. В запросах API время ожидания задаётся в миллисекундах; перевод секунд в миллисекунды выполняет сервис.
- Значение по умолчанию применяется только при отсутствии параметра. Явно заданное значение не заменяется значением по умолчанию.
- Значения по умолчанию относятся к поведению сервиса и не передаются в Kafka как часть записи.
- Написание имён параметров совпадает с реализацией и не переводится: `cluster`, `httpHost`, `httpPort`, `publisherTopics`, `autoDeleteSlotsSeconds`, `consumerIdleSeconds`, `consumerGroupPrefix`, `defaultWaitSeconds`.
- Параметры `httpHost` и `httpPort` относятся только к HTTP-серверу нашего сервиса и не влияют на подключение к Kafka.
- Источник значений, приоритеты и правила загрузки описаны в разделе «Источник настроек и приоритеты»; числовые ограничения и арифметика времени — в разделе «Числовые ограничения и безопасная арифметика времени».

## Источник настроек и приоритеты

Единственный источник настроек сервиса — переменные окружения процесса. Файлы конфигурации, аргументы командной строки и удалённые источники настроек не используются.

| Параметр | Переменная окружения |
| --- | --- |
| `cluster` | `KAFKA_TESTING_REST_CLUSTER` |
| `httpHost` | `KAFKA_TESTING_REST_HTTP_HOST` |
| `httpPort` | `KAFKA_TESTING_REST_HTTP_PORT` |
| `publisherTopics` | `KAFKA_TESTING_REST_PUBLISHER_TOPICS` |
| `autoDeleteSlotsSeconds` | `KAFKA_TESTING_REST_AUTO_DELETE_SLOTS_SECONDS` |
| `consumerIdleSeconds` | `KAFKA_TESTING_REST_CONSUMER_IDLE_SECONDS` |
| `consumerGroupPrefix` | `KAFKA_TESTING_REST_CONSUMER_GROUP_PREFIX` |
| `defaultWaitSeconds` | `KAFKA_TESTING_REST_DEFAULT_WAIT_SECONDS` |

Правила загрузки:

- Приоритет однозначен: явно заданная переменная окружения имеет приоритет над значением по умолчанию; значение по умолчанию применяется только при отсутствии переменной.
- Отсутствие переменной и пустое значение различаются. Пустое значение для параметра, у которого есть значение по умолчанию, считается некорректным и приводит к отказу запуска, а не к подстановке значения по умолчанию.
- Значение переменной не обрезается и не нормализуется молча: ведущие и завершающие пробелы делают значение некорректным. Исключение — элементы `publisherTopics`: пробелы внутри регулярного выражения значимы и сохраняются как часть выражения.
- `publisherTopics` задаётся JSON-массивом строк, например `["^orders\\.", "^payments\\."]`. Пустой массив `[]` равнозначен отсутствию ограничений. Строка, не являющаяся JSON-массивом строк, считается некорректной. Обратная косая черта в JSON-строке экранируется, поэтому регулярное выражение `^orders\.` записывается как `"^orders\\."`.
- Числовые параметры задаются десятичной записью целого числа без знака плюс, дробной части, экспоненты и разделителей разрядов. Значение `0` для `consumerIdleSeconds` допустимо и не теряется.
- Конфигурация загружается и проверяется один раз до открытия HTTP-порта. Некорректная конфигурация останавливает запуск; частично применённая конфигурация не используется.
- Значения конфигурации не изменяются во время работы: изменение переменной окружения требует перезапуска сервиса.
- Переменные окружения с именами вне таблицы не влияют на конфигурацию сервиса и не считаются ошибкой.

## HTTP-адрес и порт сервиса

Параметры `httpHost` и `httpPort` задают, на каком сетевом интерфейсе и порту сервис принимает HTTP-запросы. Они относятся только к нашему HTTP-серверу и не являются адресом Kafka.

- Значение по умолчанию `httpHost` — `127.0.0.1`: сервис доступен только с той же машины. Это безопасное значение по умолчанию для локального инструмента тестировщика.
- Доступ с других машин включается явно: адрес прослушивания задаётся значением `0.0.0.0` для всех интерфейсов IPv4 или конкретным адресом сетевого интерфейса. Аутентификация и авторизация клиентов API в первой версии не предусмотрены, поэтому открытие сервиса в сеть выполняется осознанно.
- Для прослушивания IPv6 используется адрес `::` или конкретный адрес интерфейса IPv6; значение по умолчанию остаётся `127.0.0.1`.
- Значение по умолчанию `httpPort` — `3000`. Допустимы только целые значения от `1` до `65535` включительно; `0` не используется, поскольку автоматический выбор свободного порта не предусмотрен.
- Порт должен быть свободен на выбранном интерфейсе. Занятый порт или недоступный адрес прослушивания приводит к отказу запуска, а не к выбору другого порта.
- Адрес и порт не влияют на подключение к Kafka и не заменяют `cluster`.
- Базовый путь API `/api/v1` и пути документации `/api-docs` и `/api-docs/swagger-ui` не настраиваются и описаны в [`api.md`](api.md); параметры `httpHost` и `httpPort` задают только интерфейс и порт, на которых они доступны.

## Подключение к кластеру Kafka

Параметр `cluster` задаёт общий адрес нативного брокера Kafka для всех операций сервиса: публикации, чтения консюмерами и управления собственными группами. Параметр обязателен для сервиса: без него нельзя однозначно настроить ни одну из этих операций.

- Адрес указывается в виде `хост:порт`, например `localhost:9092`. Хост и порт непустые; порт — целое число от `1` до `65535` включительно. Схема, путь, учётные данные и список адресов через запятую не допускаются: параметр задаёт ровно один адрес.
- Один и тот же адрес используется для публикации, консюмеров и управления группами. Внешний Kafka REST API, внешний REST-прокси и отдельные адреса для публикации, наблюдения или управления группами не используются.
- Проверка формы адреса выполняется до запуска без проверки сетевой доступности. Если общий брокер недоступен, соответствующие операции завершаются отказом; работающая публикация или наблюдение при этом не обещаются.
- `localhost:9092` — адрес по умолчанию интеграционных тестов с возможностью переопределения; для сервиса `cluster` остаётся обязательным и значения по умолчанию не имеет. Значение по умолчанию интеграционных тестов не является значением по умолчанию сервиса и не подставляется при отсутствии `cluster`.
- Отсутствие `cluster` и недоступность корректно заданного брокера — разные ситуации. Отсутствие параметра обнаруживается при загрузке конфигурации и останавливает запуск до открытия HTTP-порта; недоступность брокера обнаруживается при выполнении операции и приводит к отказу этой операции, а не к ошибке формата конфигурации.

## Защищённое подключение к Kafka

В первой версии защищённое подключение к Kafka не поддерживается: TLS и SASL не входят в состав конфигурации.

- Соединение с брокером устанавливается без шифрования канала и без аутентификации клиента.
- Такое подключение допустимо только в доверенной изолированной сети, например на локальной машине тестировщика или в закрытом тестовом контуре.
- Параметры TLS и SASL не вводятся: их отсутствие не является ошибкой конфигурации, а попытка подключиться к брокеру, требующему защищённое соединение, завершается отказом операции.
- Переменные окружения с именами TLS и SASL не входят в таблицу параметров, не влияют на конфигурацию и не включают защиту.
- Расширение конфигурации защищённым подключением — отдельное изменение контракта, а не настройка существующих параметров.

## Разрешённые топики публикации

Параметр `publisherTopics` — список регулярных выражений, которым должен соответствовать топик публикации.

- Пустой список означает отсутствие ограничений: публикация разрешена в любой топик. Отсутствие параметра равнозначно пустому списку.
- Непустой список требует совпадения хотя бы с одним регулярным выражением. Несовпадение ни с одним выражением означает отказ публикации до обращения к Kafka.
- Проверка выполняется только при публикации. Наблюдение за топиком через слот от этого списка не зависит: слот можно открыть по любому топику.
- Регулярные выражения сравниваются с полным именем топика; частичное совпадение по подстроке не является совпадением, если это не задано самим выражением.

## Жизненный цикл слотов

Параметр `autoDeleteSlotsSeconds` задаёт срок автоматического удаления слота по умолчанию.

- Значение применяется, только если в запросе регистрации слота поле `autoDeleteSeconds` отсутствует.
- Срок отсчитывается от момента регистрации слота и далее не пересчитывается: поступление записей, регистрация ожиданий и операции чтения срок не продлевают.
- Фактическое удаление выполняет планировщик очистки слотов с фиксированным интервалом 1 минута, поэтому слот остаётся доступным до ближайшего прохода после истечения срока.
- Приоритет значения слота над значением по умолчанию описан в разделе «Приоритеты и значения параметров слота».

## Время бездействия консюмеров

Параметр `consumerIdleSeconds` задаёт, сколько консюмер должен жить после закрытия последнего слота своего топика.

- При открытии слота время жизни консюмера вычисляется как `now() + consumerIdleSeconds + autoDeleteSeconds`, где `autoDeleteSeconds` — эффективный срок открываемого слота.
- Время жизни только увеличивается: новое значение применяется, лишь если оно больше текущего.
- Консюмер не останавливается, пока у него есть активные слоты, даже если время жизни истекло.
- Остановку по бездействию выполняет планировщик проверки бездействия консюмеров с фиксированным интервалом 10 минут; параметром конфигурации интервал не настраивается.
- Значение `0` допускает остановку консюмера сразу после закрытия последнего слота, но не раньше ближайшего прохода планировщика.

## Префикс группы консюмеров

Параметр `consumerGroupPrefix` задаёт префикс имени группы консюмеров (consumer group). Значение по умолчанию — `testing-REST-API`.

### Формирование имени группы

Имя группы создаётся отдельно для каждого топика по шаблону:

```
{prefix}-{uuid}-{topicHash}
```

- `{prefix}` — значение параметра `consumerGroupPrefix`.
- `{uuid}` — уникальный идентификатор запуска приложения. Он создаётся один раз при старте и одинаков для всех групп этого запуска; при перезапуске создаётся новый.
- `{topicHash}` — беззнаковое 64-битное число, полученное из имени топика.

Правила вычисления `{topicHash}`:

1. Имя топика берётся в точном виде, в котором оно пришло в запросе, и кодируется в UTF-8 без нормализации, обрезки пробелов и изменения регистра.
2. Вычисляется MD5 от полученных байтов; используется только первые 8 байтов дайджеста.
3. Эти 8 байтов читаются от старшего к младшему и образуют беззнаковое 64-битное число.
4. Число записывается в десятичном виде без ведущих нулей; значение `0` записывается как `0`.

Свойства имени:

- Имя группы зависит от топика: у разных топиков разные группы, поэтому закрытие консюмера одного топика не затрагивает группы других топиков. Исключение — совпадение 64-битных отпечатков, описанное ниже.
- Имя группы одного топика не меняется в пределах запуска приложения: повторное открытие консюмера по тому же топику использует то же имя.
- Два одновременно работающих экземпляра сервиса с одинаковым префиксом не попадают в одну группу, поскольку различаются идентификатором запуска.
- Два запуска одного экземпляра с одинаковым префиксом также не попадают в одну группу: идентификатор запуска у них разный.
- 64-битный отпечаток не гарантирует отсутствие коллизий: теоретически два разных имени топика могут дать одно число. При совпадении отпечатков группы двух топиков совпадут, поэтому реализация должна обнаруживать такое совпадение в пределах запуска и регистрировать его в журнале.
- Символы имени группы должны быть допустимы в Kafka: латинские буквы, цифры, точка, дефис и подчёркивание. Значение по умолчанию и десятичный суффикс этому требованию соответствуют.
- Пустое значение параметра недопустимо: оно не позволяет отличить группы разных запусков друг от друга.

### Удаление группы при закрытии консюмера

- После закрытия консюмера — по истечении времени бездействия или перед выходом из программы — сервис делает попытку удалить группу этого топика из Kafka.
- Удаление группы выполняется после освобождения ресурсов консюмера: подписка снята, клиент Kafka закрыт, запись удалена из реестра консюмеров.
- Попытка удаления не выполняется, если консюмер не был создан: при отказе создания консюмера группа не удаляется.
- Группа принадлежит одному топику, поэтому удаление не затрагивает консюмеров других топиков и обычно завершается успешно. Ошибка удаления записывается в журнал, и выполнение остальных операций продолжается: закрытие следующего консюмера, обработка запросов и фоновая очистка не прерываются.
- Удаление группы выполняется при каждом закрытии консюмера, в том числе при закрытии по бездействию. Это желаемое поведение: при следующем открытии консюмера записи, пришедшие за время отключения, не воспроизводятся.
- Ошибка удаления группы не изменяет состояние слотов, накопленных записей и ожиданий и не влияет на коды ответов API.
- Если группа удалена, а затем по тому же топику открывается новый слот, консюмер создаётся заново с тем же именем группы: удаление группы не запрещает повторное открытие. Повторное открытие выполняется после завершения попытки удаления предыдущей группы этого топика.
- Перед выходом из программы попытка удаления выполняется для каждого закрытого консюмера; её результат только записывается в журнал и не препятствует завершению работы.
- Если при завершении работы консюмеров не было, попытки удаления не выполняются: удалять нечего.

### Влияние на позицию чтения

- При каждом открытии консюмер начинает чтение с конца разделов топика, а не с сохранённых смещений (`offset`). Поэтому записи, пришедшие за время, пока консюмер был закрыт, в слот не попадают и не искажают время асинхронных откликов.
- Начало с конца разделов задаётся явно при подписке и не зависит от того, существовала ли группа ранее и какие смещения в ней могли сохраниться.
- Чтение с конца выполняется независимо от результата предыдущего удаления группы: даже если удаление завершилось ошибкой, записи за период отключения не воспроизводятся.
- Записи, опубликованные до открытия первого слота по топику, в слот не попадают.
- Удаление группы не восстанавливает и не сбрасывает позицию чтения: повторно созданный консюмер снова начинает с конца разделов.

## Время ожидания по умолчанию

Параметр `defaultWaitSeconds` задаёт тайм-аут ожидания записей, применяемый, когда в запросе ожидания отсутствует параметр `timeoutMs`.

- Значение задаётся в секундах и переводится сервисом в миллисекунды при обработке запроса по правилам раздела «Числовые ограничения и безопасная арифметика времени».
- Тайм-аут не влияет на накопление: записи, пришедшие после истечения времени, остаются в слоте и доступны методам подсчёта и чтения.
- Тайм-аут ограничивает только длительность ожидания и не изменяет срок жизни слота.

## Числовые ограничения и безопасная арифметика времени

Раздел фиксирует общие правила для всех числовых параметров конфигурации и для вычислений времени, которые из них следуют.

### Ограничения чисел

- Все числовые параметры конфигурации — целые числа. Дробные значения, отрицательные значения, знак плюс, экспоненциальная запись, разделители разрядов и значения с переполнением недопустимы и приводят к отказу запуска.
- Временные параметры `autoDeleteSlotsSeconds`, `consumerIdleSeconds` и `defaultWaitSeconds` ограничены диапазоном от `0` до `2147483647` включительно. Верхняя граница равна максимальному 32-битному знаковому целому и выбрана так, чтобы значение секунд оставалось представимым при переводе в миллисекунды без потери точности.
- Для `autoDeleteSlotsSeconds` и `defaultWaitSeconds` дополнительно требуется значение не меньше `1`: ноль для них недопустим. Для `consumerIdleSeconds` ноль допустим и означает отсутствие дополнительного времени бездействия.
- `httpPort` ограничен диапазоном от `1` до `65535` включительно; порт `cluster` — тем же диапазоном.
- Значение, выходящее за границу диапазона, не заменяется ближайшей допустимой границей и не обрезается: оно отклоняется.
- Ограничения применяются к параметрам конфигурации. Ограничения параметров запроса `n`, `timeoutMs`, `offset` и `count` задаются контрактом API в [`api.md`](api.md) и здесь не дублируются.
- Ограничения не зависят от разрядности процесса: они заданы контрактом, а не размером машинного слова.

### Безопасный перевод секунд в миллисекунды

- Перевод выполняется умножением на `1000` в целочисленной арифметике. При верхней границе `2147483647` секунд результат равен `2147483647000` миллисекунд и остаётся точным целым числом в пределах безопасного целого JavaScript (`Number.MAX_SAFE_INTEGER`).
- Перевод не выполняется через значение с плавающей точкой, которое могло бы потерять точность, и не округляется: дробных миллисекунд не возникает.
- Если значение параметра уже вышло за допустимый диапазон, перевод не выполняется: конфигурация отклоняется на этапе проверки, а не даёт переполненное или отрицательное время.
- Переведённое значение используется как тайм-аут ожидания по умолчанию и как слагаемое при вычислении времени жизни консюмера.
- При обработке запроса перевод выполняется только для значения в секундах; уже полученное миллисекундное значение повторно не умножается. Значение `timeoutMs` из запроса уже задано в миллисекундах и не переводится повторно. Ограничения параметров запроса описаны в [`api.md`](api.md).

### Безопасное сложение сроков

- Время жизни консюмера вычисляется как `now() + consumerIdleSeconds + autoDeleteSeconds`. Сумма двух параметров не превышает `4294967294` секунд, что при переводе в миллисекунды остаётся в пределах безопасного целого.
- Сложение выполняется в целочисленной арифметике над уже проверенными значениями параметров; результат сравнивается с текущим временем жизни и применяется только при увеличении.
- Если вычисленная сумма выходит за пределы безопасного целого, значение считается недопустимым и не применяется; молчаливое переполнение и превращение большого срока в отрицательный или почти нулевой не допускается.
- Срок слота и время жизни консюмера вычисляются от текущего момента; при переводе в миллисекунды используется то же безопасное правило, что и для тайм-аута ожидания.

### Длительные ожидания и системный таймер

- Тайм-аут ожидания может быть длительным. Значение не передаётся системному таймеру целиком, если оно превышает максимальную задержку, поддерживаемую средой выполнения: длительное ожидание разбивается на последовательные интервалы, каждый из которых не превышает допустимый предел.
- Разбиение не изменяет наблюдаемое поведение: ожидание завершается по условию, по истечении полного тайм-аута или при удалении слота, а не раньше срока.
- Большой тайм-аут не превращается в почти немедленный: превышение предела системного таймера не приводит к срабатыванию ожидания сразу после регистрации.
- Отмена ожидания снимает все запланированные интервалы, поэтому после завершения ожидания не остаётся активных таймеров.
- Предел одного интервала и способ разбиения относятся к реализации и не являются параметрами конфигурации; контракт фиксирует только наблюдаемое поведение.

## Приоритеты и значения параметров слота

| Параметр запроса | Значение по умолчанию | Приоритет |
| --- | --- | --- |
| `autoDeleteSeconds` | `autoDeleteSlotsSeconds` | Значение из запроса имеет приоритет и не заменяется значением по умолчанию |
| `timeoutMs` | `defaultWaitSeconds`, переведённое в миллисекунды | Значение из запроса имеет приоритет |
| `n` | `1` | Значение из запроса имеет приоритет |
| `offset` | `0` | Значение из запроса имеет приоритет |
| `count` | `20` | Значение из запроса имеет приоритет |

Правила:

- Значение по умолчанию применяется только при отсутствии параметра. Некорректное значение не заменяется значением по умолчанию: запрос отклоняется согласно [`api.md`](api.md).
- Срок слота фиксируется в момент регистрации и не зависит от последующих изменений конфигурации.
- Время жизни консюмера вычисляется по эффективному сроку слота, то есть по значению, выбранному с учётом приоритета.

## Проверка конфигурации и типичные ошибки

При запуске сервис проверяет конфигурацию и не начинает работу при нарушениях. Проверка выполняется до открытия HTTP-порта, поэтому некорректная конфигурация не приводит к частично работающему сервису.

| Ситуация | Поведение |
| --- | --- |
| Не задан `cluster` | Запуск невозможен: общий нативный адрес Kafka для публикации, чтения и управления группами не задан |
| `cluster` не соответствует формату `хост:порт`, содержит схему, путь, учётные данные или список адресов, либо порт вне диапазона `1`–`65535` | Запуск невозможен: адрес общего брокера не определён |
| `httpHost` пуст или не является допустимым адресом прослушивания | Запуск невозможен: сервис не смог бы принимать запросы |
| `httpPort` вне диапазона `1`–`65535` или не является целым числом | Запуск невозможен: порт HTTP-сервера не определён |
| `httpPort` занят на выбранном интерфейсе | Запуск невозможен: сервис не подменяет порт другим |
| `autoDeleteSlotsSeconds` не больше нуля или больше `2147483647` | Запуск невозможен: слот не смог бы истечь или срок не представим |
| `consumerIdleSeconds` меньше нуля или больше `2147483647` | Запуск невозможен: время жизни консюмера не определено |
| `defaultWaitSeconds` не больше нуля или больше `2147483647` | Запуск невозможен: ожидание завершалось бы сразу или тайм-аут не представим |
| Числовой параметр задан дробью, со знаком плюс, экспонентой или разделителями разрядов | Запуск невозможен: значение не является допустимым целым |
| Пустой `consumerGroupPrefix` | Запуск невозможен: имя группы не позволяет отличить запуски друг от друга |
| Некорректное регулярное выражение в `publisherTopics` | Запуск невозможен: правило разрешения топиков не определено |
| `publisherTopics` не является JSON-массивом строк | Запуск невозможен: список разрешённых топиков не определён |
| Отсутствие `consumerGroupPrefix` | Применяется значение по умолчанию `testing-REST-API` |
| Отсутствие `publisherTopics` | Применяется пустой список: ограничений нет |
| Отсутствие `httpHost` или `httpPort` | Применяются значения по умолчанию `127.0.0.1` и `3000` |
| Отсутствие `autoDeleteSlotsSeconds`, `consumerIdleSeconds` или `defaultWaitSeconds` | Применяются значения по умолчанию `60`, `3600` и `60` секунд |
| Пустое значение переменной окружения | Запуск невозможен: пустое значение не заменяется значением по умолчанию |

Типичные ошибки эксплуатации:

- Одинаковый `consumerGroupPrefix` у нескольких экземпляров не приводит к общей группе, поскольку имя дополняется идентификатором запуска; при этом удаление группы одним экземпляром не затрагивает группы других экземпляров.
- Одинаковый `consumerGroupPrefix` у двух запусков одного экземпляра также не приводит к общей группе: идентификатор запуска у них разный.
- Группа принадлежит одному топику, поэтому удаление после закрытия консюмера не затрагивает консюмеров других топиков; ошибка удаления возможна, но не является ожидаемым штатным исходом.
- Ошибка удаления группы не влияет на коды ответов API и не изменяет состояние слотов, накопленных записей и ожиданий: она только записывается в журнал.
- Совпадение 64-битных отпечатков двух разных имён топиков приводит к совпадению имён групп; реализация обнаруживает такое совпадение в пределах запуска и регистрирует его в журнале.
- Изменение `autoDeleteSlotsSeconds` не влияет на уже открытые слоты: их срок зафиксирован при регистрации.
- Отсутствие `cluster` и недоступность корректно заданного брокера различаются: первое останавливает запуск, второе приводит к отказу операции. Не следует считать отказ операции признаком ошибки конфигурации.
- Значение по умолчанию `httpHost` `127.0.0.1` не делает сервис доступным из сети. Для доступа с других машин адрес прослушивания задаётся явно, с учётом отсутствия аутентификации клиентов API.
- `localhost:9092` — значение по умолчанию интеграционных тестов, а не сервиса. Запуск сервиса без `cluster` не подставляет этот адрес.
- Защищённое подключение к Kafka в первой версии не поддерживается: брокер, требующий TLS или SASL, недоступен для сервиса, и это не исправляется настройкой существующих параметров.
