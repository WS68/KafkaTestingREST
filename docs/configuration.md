# Конфигурация

Документ описывает параметры конфигурации сервиса, их типы, значения по умолчанию, ограничения и влияние на публикацию, консюмеров и жизненный цикл слотов. Контракт HTTP API описывается в [`api.md`](api.md), а внутреннее устройство и алгоритмы работы — в [`architecture.md`](architecture.md). Назначение проекта, требования к запуску и инструкции по сборке остаются в [`../readme.md`](../readme.md); правила документирования определены в [`../AGENTS.md`](../AGENTS.md).

- Приоритеты и значения параметров слота
- Проверка конфигурации и типичные ошибки

## Общие правила конфигурации

| Параметр | Тип | Обязательность | Значение по умолчанию | Ограничения | Влияние на поведение сервиса |
| --- | --- | --- | --- | --- | --- |
| `cluster` | строка | Да | Нет | Формат `хост:порт` | Определяет адрес Kafka для публикации; на наблюдение за топиками не влияет |
| `publisherTopics` | массив строк | Нет | Пустой список | Каждый элемент — регулярное выражение; пустой список допустим | Разрешает публикацию только в соответствующие топики; на наблюдение через слоты не влияет |
| `autoDeleteSlotsSeconds` | целое, больше нуля | Нет | `60` секунд (1 минута) | Только положительные значения; применяется при отсутствии `autoDeleteSeconds` в запросе | Задаёт срок автоматического удаления слота по умолчанию; очистка выполняется планировщиком раз в 1 минуту |
| `consumerIdleSeconds` | целое, больше или равно нулю | Нет | `3600` секунд (1 час) | Нулевое значение допустимо; интервал проверки 10 минут параметром не настраивается | Определяет дополнительное время жизни консюмера после закрытия последнего слота |
| `consumerGroupPrefix` | строка | Нет | `testing-REST-API` | Непустое значение; допустимы символы имени группы Kafka: латинские буквы, цифры, точка, дефис и подчёркивание | Участвует в формировании отдельной группы консюмера для каждого топика |
| `defaultWaitSeconds` | целое, больше нуля | Нет | `60` секунд (1 минута) | Только положительные значения; применяется при отсутствии `timeoutMs` в запросе | Задаёт тайм-аут ожидания записей по умолчанию и не влияет на накопление записей или срок жизни слота |

Правила:

- Все временные параметры задаются в секундах. В запросах API время ожидания задаётся в миллисекундах; перевод секунд в миллисекунды выполняет сервис.
- Значение по умолчанию применяется только при отсутствии параметра. Явно заданное значение не заменяется значением по умолчанию.
- Значения по умолчанию относятся к поведению сервиса и не передаются в Kafka как часть записи.
- Написание имён параметров совпадает с реализацией и не переводится: `cluster`, `publisherTopics`, `autoDeleteSlotsSeconds`, `consumerIdleSeconds`, `consumerGroupPrefix`, `defaultWaitSeconds`.

## Подключение к кластеру Kafka

Параметр `cluster` задаёт адрес, по которому сервис публикует записи через Kafka REST API. Параметр обязателен: без него публикация невозможна.

- Адрес указывается в виде `хост:порт`, например `localhost:9092`.
- Параметр используется только ветвью публикации. Консюмеры подключаются к кластеру независимо от значения этого параметра.
- Недоступность адреса не блокирует запуск сервиса: публикация в этом случае завершается отказом, а наблюдение за топиками продолжает работать.

## Разрешённые топики публикации

Параметр `publisherTopics` — список регулярных выражений, которым должен соответствовать топик публикации.

- Пустой список означает отсутствие ограничений: публикация разрешена в любой топик. Отсутствие параметра равнозначно пустому списку.
- Непустой список требует совпадения хотя бы с одним регулярным выражением. Несовпадение ни с одним выражением означает отказ публикации до обращения к Kafka.
- Проверка выполняется только при публикации. Наблюдение за топиком через слот от этого списка не зависит: слот можно открыть по любому топику.
- Регулярные выражения сравниваются с полным именем топика; частичное совпадение по подстроке не является совпадением, если это не задано самим выражением.

## Жизненный цикл слотов

Параметр `autoDeleteSlotsSeconds` задаёт срок автоматического удаления слота по умолчанию.

- Значение применяется, только если в запросе регистрации слота поле `autoDeleteSeconds` отсутствует.
- Срок отсчитывается от момента регистрации слота и далее не пересчитывается: поступление записей, регистрация ожиданий и операции чтения срок не продлевают.
- Фактическое удаление выполняет планировщик очистки слотов с фиксированным интервалом 1 минута, поэтому слот остаётся доступным до ближайшего прохода после истечения срока.
- Приоритет значения слота над значением по умолчанию описан в разделе «Приоритеты и значения параметров слота».

## Время бездействия консюмеров

Параметр `consumerIdleSeconds` задаёт, сколько консюмер должен жить после закрытия последнего слота своего топика.

- При открытии слота время жизни консюмера вычисляется как `now() + consumerIdleSeconds + autoDeleteSeconds`, где `autoDeleteSeconds` — эффективный срок открываемого слота.
- Время жизни только увеличивается: новое значение применяется, лишь если оно больше текущего.
- Консюмер не останавливается, пока у него есть активные слоты, даже если время жизни истекло.
- Остановку по бездействию выполняет планировщик проверки бездействия консюмеров с фиксированным интервалом 10 минут; параметром конфигурации интервал не настраивается.
- Значение `0` допускает остановку консюмера сразу после закрытия последнего слота, но не раньше ближайшего прохода планировщика.

## Префикс группы консюмеров

Параметр `consumerGroupPrefix` задаёт префикс имени группы консюмеров (consumer group). Значение по умолчанию — `testing-REST-API`.

### Формирование имени группы

Имя группы создаётся отдельно для каждого топика по шаблону:

```
{prefix}-{uuid}-{topicHash}
```

- `{prefix}` — значение параметра `consumerGroupPrefix`.
- `{uuid}` — уникальный идентификатор запуска приложения. Он создаётся один раз при старте и одинаков для всех групп этого запуска; при перезапуске создаётся новый.
- `{topicHash}` — беззнаковое 64-битное число, полученное из имени топика.

Правила вычисления `{topicHash}`:

1. Имя топика берётся в точном виде, в котором оно пришло в запросе, и кодируется в UTF-8 без нормализации, обрезки пробелов и изменения регистра.
2. Вычисляется MD5 от полученных байтов; используется только первые 8 байтов дайджеста.
3. Эти 8 байтов читаются от старшего к младшему и образуют беззнаковое 64-битное число.
4. Число записывается в десятичном виде без ведущих нулей; значение `0` записывается как `0`.

Свойства имени:

- Имя группы зависит от топика: у разных топиков разные группы, поэтому закрытие консюмера одного топика не затрагивает группы других топиков. Исключение — совпадение 64-битных отпечатков, описанное ниже.
- Имя группы одного топика не меняется в пределах запуска приложения: повторное открытие консюмера по тому же топику использует то же имя.
- Два одновременно работающих экземпляра сервиса с одинаковым префиксом не попадают в одну группу, поскольку различаются идентификатором запуска.
- Два запуска одного экземпляра с одинаковым префиксом также не попадают в одну группу: идентификатор запуска у них разный.
- 64-битный отпечаток не гарантирует отсутствие коллизий: теоретически два разных имени топика могут дать одно число. При совпадении отпечатков группы двух топиков совпадут, поэтому реализация должна обнаруживать такое совпадение в пределах запуска и регистрировать его в журнале.
- Символы имени группы должны быть допустимы в Kafka: латинские буквы, цифры, точка, дефис и подчёркивание. Значение по умолчанию и десятичный суффикс этому требованию соответствуют.
- Пустое значение параметра недопустимо: оно не позволяет отличить группы разных запусков друг от друга.

### Удаление группы при закрытии консюмера

- После закрытия консюмера — по истечении времени бездействия или перед выходом из программы — сервис делает попытку удалить группу этого топика из Kafka.
- Удаление группы выполняется после освобождения ресурсов консюмера: подписка снята, клиент Kafka закрыт, запись удалена из реестра консюмеров.
- Попытка удаления не выполняется, если консюмер не был создан: при отказе создания консюмера группа не удаляется.
- Группа принадлежит одному топику, поэтому удаление не затрагивает консюмеров других топиков и обычно завершается успешно. Ошибка удаления записывается в журнал, и выполнение остальных операций продолжается: закрытие следующего консюмера, обработка запросов и фоновая очистка не прерываются.
- Удаление группы выполняется при каждом закрытии консюмера, в том числе при закрытии по бездействию. Это желаемое поведение: при следующем открытии консюмера записи, пришедшие за время отключения, не воспроизводятся.
- Ошибка удаления группы не изменяет состояние слотов, накопленных записей и ожиданий и не влияет на коды ответов API.
- Если группа удалена, а затем по тому же топику открывается новый слот, консюмер создаётся заново с тем же именем группы: удаление группы не запрещает повторное открытие. Повторное открытие выполняется после завершения попытки удаления предыдущей группы этого топика.
- Перед выходом из программы попытка удаления выполняется для каждого закрытого консюмера; её результат только записывается в журнал и не препятствует завершению работы.
- Если при завершении работы консюмеров не было, попытки удаления не выполняются: удалять нечего.

### Влияние на позицию чтения

- При каждом открытии консюмер начинает чтение с конца разделов топика, а не с сохранённых смещений (`offset`). Поэтому записи, пришедшие за время, пока консюмер был закрыт, в слот не попадают и не искажают время асинхронных откликов.
- Начало с конца разделов задаётся явно при подписке и не зависит от того, существовала ли группа ранее и какие смещения в ней могли сохраниться.
- Чтение с конца выполняется независимо от результата предыдущего удаления группы: даже если удаление завершилось ошибкой, записи за период отключения не воспроизводятся.
- Записи, опубликованные до открытия первого слота по топику, в слот не попадают.
- Удаление группы не восстанавливает и не сбрасывает позицию чтения: повторно созданный консюмер снова начинает с конца разделов.

## Время ожидания по умолчанию

Параметр `defaultWaitSeconds` задаёт тайм-аут ожидания записей, применяемый, когда в запросе ожидания отсутствует параметр `timeoutMs`.

- Значение задаётся в секундах и переводится сервисом в миллисекунды при обработке запроса.
- Тайм-аут не влияет на накопление: записи, пришедшие после истечения времени, остаются в слоте и доступны методам подсчёта и чтения.
- Тайм-аут ограничивает только длительность ожидания и не изменяет срок жизни слота.

## Приоритеты и значения параметров слота

| Параметр запроса | Значение по умолчанию | Приоритет |
| --- | --- | --- |
| `autoDeleteSeconds` | `autoDeleteSlotsSeconds` | Значение из запроса имеет приоритет и не заменяется значением по умолчанию |
| `timeoutMs` | `defaultWaitSeconds`, переведённое в миллисекунды | Значение из запроса имеет приоритет |
| `n` | `1` | Значение из запроса имеет приоритет |
| `offset` | `0` | Значение из запроса имеет приоритет |
| `count` | `20` | Значение из запроса имеет приоритет |

Правила:

- Значение по умолчанию применяется только при отсутствии параметра. Некорректное значение не заменяется значением по умолчанию: запрос отклоняется согласно [`api.md`](api.md).
- Срок слота фиксируется в момент регистрации и не зависит от последующих изменений конфигурации.
- Время жизни консюмера вычисляется по эффективному сроку слота, то есть по значению, выбранному с учётом приоритета.

## Проверка конфигурации и типичные ошибки

При запуске сервис проверяет конфигурацию и не начинает работу при нарушениях:

| Ситуация | Поведение |
| --- | --- |
| Не задан `cluster` | Запуск невозможен: публикация недоступна |
| `autoDeleteSlotsSeconds` не больше нуля | Запуск невозможен: слот не смог бы истечь |
| `consumerIdleSeconds` меньше нуля | Запуск невозможен: время жизни консюмера не определено |
| `defaultWaitSeconds` не больше нуля | Запуск невозможен: ожидание завершалось бы сразу |
| Пустой `consumerGroupPrefix` | Запуск невозможен: имя группы не позволяет отличить запуски друг от друга |
| Некорректное регулярное выражение в `publisherTopics` | Запуск невозможен: правило разрешения топиков не определено |
| Отсутствие `consumerGroupPrefix` | Применяется значение по умолчанию `testing-REST-API` |
| Отсутствие `publisherTopics` | Применяется пустой список: ограничений нет |

Типичные ошибки эксплуатации:

- Одинаковый `consumerGroupPrefix` у нескольких экземпляров не приводит к общей группе, поскольку имя дополняется идентификатором запуска; при этом удаление группы одним экземпляром не затрагивает группы других экземпляров.
- Одинаковый `consumerGroupPrefix` у двух запусков одного экземпляра также не приводит к общей группе: идентификатор запуска у них разный.
- Группа принадлежит одному топику, поэтому удаление после закрытия консюмера не затрагивает консюмеров других топиков; ошибка удаления возможна, но не является ожидаемым штатным исходом.
- Ошибка удаления группы не влияет на коды ответов API и не изменяет состояние слотов, накопленных записей и ожиданий: она только записывается в журнал.
- Совпадение 64-битных отпечатков двух разных имён топиков приводит к совпадению имён групп; реализация обнаруживает такое совпадение в пределах запуска и регистрирует его в журнале.
- Изменение `autoDeleteSlotsSeconds` не влияет на уже открытые слоты: их срок зафиксирован при регистрации.
